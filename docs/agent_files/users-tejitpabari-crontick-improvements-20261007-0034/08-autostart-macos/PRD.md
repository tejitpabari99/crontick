# PRD: AutoStart macOS backend (SP08)

**Repo/branch:** /root/projects/crontick-wt-improvements, `users/tejitpabari/crontick-improvements`
**Depends on:** SP07 (`AutostartBackend`, `AutostartService`, factory in `src/autostart/index.ts`)
**Owns:** `src/autostart/{launchd,plist}.ts` (new), one `case 'darwin'` in `src/autostart/index.ts`, `tests/unit/autostart-launchd*.test.ts`, `docs/reference/cli.md` macOS notes, `docs/concepts/daemon-lifecycle.md` macOS section, macOS section of ADR 0034, changeset entry (if SP07's is not reused).

## TL;DR

Implement `AutostartBackend` for `mechanism: 'launchd'`. `install` writes `~/Library/LaunchAgents/<label>.plist` (generated by string, XML-escaped, no deps) and runs `launchctl bootstrap gui/$UID <plist>`; `uninstall` does `bootout` + delete; `inspect` parses the plist plus `launchctl print` / `print-disabled`. Starts at login only, no admin, no signing. Honest limitation: macOS 13+ lists the agent in System Settings > Login Items as an unsigned "node" item and the user can switch it off; we detect and report that where we can. Cannot run in CI (no macOS runner), so correctness rests on injected-exec unit tests plus an owner real-Mac checklist.

## Problem

- SP07 ships Linux only; `createAutostartBackend` returns `undefined` for darwin, so `autostart enable` throws `AUTOSTART_UNSUPPORTED` on macOS.
- Old darwin stub only sketched `com.crontick.daemon.plist` + legacy `launchctl load/unload` + `launchctl list` `[verified: git show f24ae58:src/autostart/darwin.ts]`. Legacy verbs always exit 0 except misuse, so they cannot signal failure `[https://keith.github.io/xcode-man-pages/launchctl.1.html]`.
- Since macOS 13, every third-party plist surfaces in Login Items and fires a "Background Items Added" notification; unsigned items show as "unidentified developer" with generic names and are hard to identify `[https://eclecticlight.co/2023/02/15/controlling-login-and-background-items-in-ventura/]`.
- launchd has no equivalent of systemd `SuccessExitStatus`, so SP07 makes the daemon exit 0 when `CRONTICK_SUPERVISED=1` (instead of a special exit code) to avoid a respawn loop when a demand-started daemon already holds the PID file `[verified: SP07 PRD; launchd.plist(5) KeepAlive]`.

## Goals / Non-Goals

**Goals:** opt-in, admin-free, transparent plist; idempotent install/uninstall; `inspect()` reports registered / enabled / running / disabled-by-user; detached job runs survive daemon stop/restart; zero new deps; fully unit-testable via injected exec/fs.
**Non-Goals:** boot-time start (LaunchDaemon, needs root); Developer ID signing/notarization or an app-bundle `SMAppService` helper (owner option, see Manual steps and `futures.md`); Full Disk Access management; legacy `launchctl load/unload` fallback; multiple data dirs.

## Architecture

**Label and path.** Label `dev.crontick.daemon` `[RESOLVED: owner accepted `dev.crontick.daemon`]`; file `~/Library/LaunchAgents/dev.crontick.daemon.plist`. Domain target `gui/$(id -u)` (per-user GUI session) `[https://keith.github.io/xcode-man-pages/launchctl.1.html]`.

**Plist keys** (verified against launchd.plist(5) `[https://keith.github.io/xcode-man-pages/launchd.plist.5.html]` unless tagged):

| Key | Value | Rationale |
|---|---|---|
| `Label` | `dev.crontick.daemon` | unique id |
| `ProgramArguments` | `[nodePath, daemonScript]` | absolute, from `AutostartSpec`; script is foreground, takes no argv (SP07 D3) |
| `EnvironmentVariables` | `spec.env` (`CRONTICK_SUPERVISED=1`, `CRONTICK_HOME` if set, `PATH` snapshot; all built by SP07 core `buildSpec`, this backend adds nothing) | launchd agents get a minimal PATH, so engines like `claude` need the snapshot; matches SP07 D5 `[inferred: man page gives no default PATH]` |
| `RunAtLoad` | `true` | start at login (agents load at login) |
| `KeepAlive` | `{SuccessfulExit: false}` | restart only after non-zero/crash; exit 0 (graceful `daemon stop`) stays down. Semantics: restart if exit status is non-zero. Implies RunAtLoad |
| `ThrottleInterval` | `30` | default is 10 s; slower to bound any respawn loop |
| `ProcessType` | omit (Standard) | `Background` applies resource limits (CPU/IO) that children inherit `[inferred]`, bad for engine runs; not `Interactive` |
| `AbandonProcessGroup` | `true` | launchd otherwise kills remaining processes in the job's process group when it dies; this is the closest analogue to systemd `KillMode=process`, keeping adopted detached runs alive across daemon stop/restart |
| `StandardOutPath` / `StandardErrorPath` | `<logsDir>/launchd.out.log` / `launchd.err.log` | `logsDir` from `src/paths.ts` using spec `CRONTICK_HOME`; launchd does not create parent dirs, so install mkdirs it. Sits beside `daemon.ensure.log` |
| `WorkingDirectory` | data dir (`dataDir()`) | avoids `/` cwd and any TCC-protected cwd |
| `ExitTimeOut` | omit (default) | |

Never set: `LimitLoadToSessionType` (default fine), `AssociatedBundleIdentifiers` (needs a signed app bundle), `Disabled`.

**launchctl calls** (all via injected `exec(file,args)`, `file='/bin/launchctl'`):

| Op | argv |
|---|---|
| probe session | `print gui/<uid>` |
| loaded? | `print gui/<uid>/<label>` (exit 0 = loaded; non-zero = not loaded) |
| install | `bootout gui/<uid>/<label>` (only if loaded) -> `bootstrap gui/<uid> <plist>` -> `enable gui/<uid>/<label>` |
| uninstall | `bootout gui/<uid>/<label>` |
| disabled? | `print-disabled gui/<uid>` -> line `"<label>" => disabled` |

Idempotency: re-bootstrapping a loaded service fails with an opaque "5: Input/output error", and a lingering disable record from an earlier `bootout`/`disable` does too `[https://docs.stepsecurity.io/developer-machines/installation/script/mdm-deployment/macos/launchd-troubleshooting]`. So we never blind-bootstrap: check loaded, bootout, bootstrap, and on failure with a disable record run `enable` and retry once, otherwise surface stderr in `CrontickError`. Using `enable` after every install makes the retry path rare. `launchctl print` output is "NOT API" per its man page, so parse only the minimum (`pid = N`, `state = running`, `last exit code`) tolerantly; unparseable output yields `active: undefined` plus a note, never a throw.

**Disabled-by-user detection (macOS 13+).** The Login Items toggle is BTM state, separate from launchd's own disable database; scripts cannot read BTM without `sfltool dumpbtm` (undocumented, needs sudo) `[https://mjtsai.com/blog/2023/07/05/how-to-diagnose-and-control-login-and-background-items]`. Design: `enabledInManager = !print-disabled.has(label)` and `active` from `print`. If registered, `RunAtLoad` and not loaded after bootstrap, add note "may be switched off in System Settings > General > Login Items & Extensions". We do not call `sfltool`. `[OPEN]` whether a BTM toggle-off also appears in `print-disabled` (needs real-Mac test; Eclectic Light notes toggles sometimes revert).

**TCC / Gatekeeper / keychain.**
- Gatekeeper/quarantine: files created by node are not quarantined; the plist and `node` binary run from launchd without a prompt `[inferred; verify on Mac]`.
- TCC: a launchd-started node has no Full Disk Access; reading `~/Documents`, `~/Desktop`, `~/Downloads`, iCloud, removable volumes from job cwd triggers a TCC prompt or silent denial attributed to the responsible process `[https://docs.stepsecurity.io/developer-machines/installation/script/mdm-deployment/macos]`. Hint in status: grant Full Disk Access to the node binary, or keep job dirs outside protected folders. Not managed by crontick.
- Claude auth: a GUI-session LaunchAgent can read the login keychain `[https://lilting.ch/en/articles/macos-keychain-tmux-claude-cli-auth-failure]`, but a report shows Claude CLI "Not logged in" when the process tree starts at launchd despite valid credentials, closed "not planned"; workaround is `CLAUDE_CODE_OAUTH_TOKEN` in the environment `[https://claudeissues.com/issue/77213-not-logged-in-when-the-process-tree-starts-at-launchd-despite-valid-unexpired-ke]`. `[OPEN]` impact on crontick's claude engine; verify on a real Mac and document the fallback (set token via the engine env config, not in the plist).
- nvm/Homebrew node: `process.execPath` changes on switch/upgrade; core drift flags it (R7).

**Testing without macOS CI.** CI is ubuntu/windows only `[verified: .github/workflows/ci.yml matrix]`. Unit tests (run everywhere, `platform:'darwin'` injected, fake exec/fs): plist snapshot incl. escaping and optional `CRONTICK_HOME`; `parsePlist(renderPlist(x))` round-trip; exact launchctl argv sequences for install-fresh, install-when-loaded, install-with-disable-record (enable+retry), uninstall-missing, uninstall-loaded; `inspect` against canned `print`/`print-disabled` outputs including garbage; `available()` false on missing uid/no GUI session; factory returns launchd for darwin and `undefined` for others. No `plutil` in CI; optional guarded test runs `plutil -lint` only when `process.platform==='darwin'`.

## Decisions

| # | Decision | Choice | Alternatives | Why |
|---|---|---|---|---|
| D1 | Mechanism | User LaunchAgent, `bootstrap gui/$UID` | LaunchDaemon; legacy `load`; SMAppService | No admin; legacy exits 0 on failure; SMAppService needs signed bundle |
| D2 | Start trigger | Login only (`RunAtLoad`) | Boot | Matches brainstorm; keychain/GUI session needed |
| D3 | Restart policy | `KeepAlive{SuccessfulExit:false}`, `ThrottleInterval 30` | `KeepAlive true`; none | Graceful stop stays stopped; crash recovered |
| D4 | Process-group | `AbandonProcessGroup true` | default | Runs survive daemon stop (SP07 D6 analogue) |
| D5 | ProcessType | Omit | Background | Avoid inherited throttling of engine runs |
| D6 | Logs | `<logsDir>/launchd.{out,err}.log` | `/dev/null`, `~/Library/Logs` | Single data dir, owner can inspect; reuses `logsDir` |
| D7 | Disabled detection | `print-disabled` + `print`; note, no `sfltool` | `sfltool dumpbtm` | Needs sudo, undocumented |
| D8 | Signing | None; document optional owner route | Ad-hoc/Developer ID | Out of scope per brainstorm |
| D9 | PATH | Snapshot at enable, built in core `buildSpec` | Login-shell PATH; backend-specific PATH | Same as Linux (SP07 D5); backend does not add PATH |

## Manual steps (owner-only)

1. Real-Mac checklist (macOS 13+ and ideally 15): `crontick autostart enable` -> plist at expected path, "Background Items Added" notification seen, `launchctl print gui/$UID/dev.crontick.daemon` shows running; log out/in -> daemon up; second `enable` is a no-op; `status` shows `enabled`; `disable` removes plist and Login Items entry; demand-start first then `enable` -> no respawn loop in `launchd.err.log`.

## Acceptance Criteria

1. Factory returns the launchd backend for `platform:'darwin'`; `enable|disable|status` work on macOS with SP07's service unchanged apart from the agreed delta.
2. Unit tests (fake exec/fs) pass on ubuntu and windows CI, covering every bullet in "Testing without macOS CI"; plist snapshot contains all keys in the table and nothing else.
3. install/uninstall are idempotent; no code path calls bare `bootstrap` on an already-loaded label; no legacy `load`/`unload`/`list`.
4. `inspect()` never throws on missing plist, unloaded service, or unparseable `print` output.
5. Docs (reference, lifecycle, ADR macOS section) state login-only, Login Items visibility, TCC and keychain caveats.
6. `npm run validate` passes; owner checklist results recorded on the PR before release.
