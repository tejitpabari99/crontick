Add the `webhook` schedule kind: run a job when an external event arrives, with no inbound port. `crontick jobs new|update --webhook [--relay <url|auto>] [--webhook-secret <s>]` (MCP/library schedule `{ kind: 'webhook', relay?, secret? }`); the daemon opens one outbound SSE connection per relay URL (smee.io protocol; `--relay auto` creates a smee.io channel, omit `--relay` for local-trigger-only). New `crontick jobs trigger <job> [--payload <json>|@file|->]`, MCP `crontick_job_trigger`, library `triggerJob` and `POST /api/jobs/:id/trigger` fire a webhook job locally (`NOT_WEBHOOK_JOB`, `JOB_DISABLED`, `INVALID_PAYLOAD`). Runs get `CRONTICK_TRIGGER=webhook`, `CRONTICK_EVENT`, `CRONTICK_EVENT_SOURCE` and `CRONTICK_EVENT_ID`, and the payload is appended to the prompt as fenced untrusted data (64KB cap). Relay events are HMAC-checked (`x-hub-signature-256`, unverified against real GitHub deliveries; the signature covers only the body, so signed jobs receive only `body`, and replays are deduplicated by signature), deduplicated and limited to 10 runs/minute per job; events missed while the daemon is down are not replayed. Relay URLs and secrets are redacted everywhere except `jobs get`; `share export|import` strip them unless `--include-secrets` (`includeSecrets` on MCP/library). Adds `getRelayStatus()` (library-only), `GET /api/relays`, a `relay:` line in `jobs get`, a `doctor` relay check, trigger rendering in `runs get`, and a dashboard Webhook kind with Create channel, Copy and Trigger now. Run webhook jobs with restricted engine permissions. `jobs update <job> --relay auto` (or `--webhook-secret`) alone edits an existing webhook job. See ADR 0036 and docs/concepts/webhooks.md.
